**Отчет по применению принципов SOLID в игре "Угадай число"**

### 1. Принцип единственной ответственности (SRP)
- **Класс `GameSettings`**: отвечает только за хранение настроек (диапазон чисел, количество попыток).
- **Класс `RandomNumberGenerator`**: генерирует случайное число в заданном диапазоне.
- **Класс `ConsoleInputHandler`**: обрабатывает ввод данных от пользователя.
- **Класс `ConsoleOutputHandler`**: выводит сообщения и подсказки.
- **Класс `Game`**: управляет процессом игры, делегируя задачи генерации, ввода и вывода соответствующим классам.

### 2. Принцип открытости/закрытости (OCP)
- **Интерфейс `ISettingsProvider`**: позволяет добавлять новые способы загрузки настроек (например, из файла, базы данных) без изменения существующего кода. Реализации: `ConsoleSettingsProvider`, `FileSettingsProvider`.
- **Интерфейс `INumberGenerator`**: можно добавить новые алгоритмы генерации чисел (например, криптографически безопасные), не меняя класс `Game`.

### 3. Принцип подстановки Лисков (LSP)
- Все реализации интерфейсов (например, `RandomNumberGenerator`, `FileSettingsProvider`) могут быть заменены на другие (например, `SecureNumberGenerator`, `DatabaseSettingsProvider`) без нарушения работы системы. Класс `Game` не зависит от конкретных реализаций.

### 4. Принцип разделения интерфейса (ISP)
- Интерфейсы `IInputHandler` и `IOutputHandler` разделены:
  - `IInputHandler` содержит только метод `int GetGuess()`.
  - `IOutputHandler` включает методы `ShowMessage`, `ShowHint`, `ShowGameOver`, что позволяет гибко настраивать вывод.

### 5. Принцип инверсии зависимостей (DIP)
- Класс `Game` зависит от абстракций:
  - Через конструктор внедряются `INumberGenerator`, `IInputHandler`, `IOutputHandler`, `GameSettings`.
